# FreeWorks – guide for Claude and other AI / developers

FreeWorks makes FreeCAD look, feel and work like SOLIDWORKS for an experienced
SOLIDWORKS user (CSWA/CSWP level), without changing FreeCAD's engine. It is a
FreeCAD add-on (`Mod/FreeWorks`) plus a Windows installer that sets up a
self-contained FreeCAD in `D:\FreeWorks`.

Repo: https://github.com/scp15156402/FreeWorks · Licence LGPL-2.1+ · Owner: Siddhant Patil

## Two commands the owner uses

### "continue"
1. Read `dev/TRACKER.md`. The **Next part** line says what to do.
2. Do that part only. Parts are sized for **≤ 30 minutes**; if a part runs long,
   split it in the tracker rather than overrunning.
3. Commit after each finished task (small commits, message + attribution lines).
4. At the end of the part: update `dev/TRACKER.md` (status, session log, next part),
   commit, push if GitHub access works (otherwise rebuild `FreeWorks.bundle`),
   and tell the owner in a few lines what was done and what comes next.

### "Let's get it up to date"
Follow `dev/UPDATE_PROTOCOL.md` exactly: check the newest FreeCAD release and
add-ons, review what changed in FreeCAD and in the latest SOLIDWORKS release,
test FreeWorks against the new FreeCAD, update `versions.json`, fix breakage,
release.

## Rules that keep FreeWorks stable and fast

- **Never crash FreeCAD.** Every callback FreeWorks registers (timers, signals,
  observers, event filters, commands) is wrapped (`@safe` or try/except) and logs
  instead of raising.
- **Never add lag.** No application-wide Qt event filters, no work on every mouse
  move outside the gesture filter on 3D viewports, timers ≤ 4 Hz and cheap,
  network only in background threads.
- FreeCAD knowledge that was verified in practice lives in `dev/DEV_NOTES.md`
  (e.g. icon override via `<UserData>/icons`, Tasks dock starts as an overlay,
  QOpenGLWidget viewport class names). Read it before touching those areas.
- Names: use SOLIDWORKS terminology; where FreeCAD differs, the tooltip says
  "(closest FreeCAD equivalent)". Never claim parity that does not exist.
- Do not put "SOLIDWORKS" in product names; icons and artwork are original.
- Installer scripts must run on Windows PowerShell 5.1.

## Testing

**Run `dev/run_tests.sh` after every change** (≈1 min, exit code 0 = pass). It does static
checks, then runs `dev/tests/suite.py` inside the pinned FreeCAD (auto-downloaded) under Xvfb:
catalog, UI, naming, Mass Properties numbers, contexts, performance budgets, error log. Add a
test to `suite.py` for every feature or bug fix. Interactive input tests (gestures, shortcuts)
are in `dev/tests/interactive/`. `dev/check_updates.py` compares pins with upstream.
Windows-only parts (installer, launcher) get `dev/tests/pscheck.py` + review; ask the owner
to report results.

## Git

Commit regularly to `main` (development). **Releasing = pushing to the `stable` branch**: the
one-line installer and the in-app update check install whatever `stable` holds and compare
versions using `Mod/FreeWorks/package.xml` there. Release steps: bump the version in
`package.xml`, `freeworks/__init__.py`, `versions.json` (`freeworks`) and `CHANGELOG.md` on `main`,
test, then `git push origin main:stable`. Only push tested work to `stable`.
Claude sessions can push branches but not tags (GitHub 403); the owner may add `vX.Y.Z` tags /
GitHub Releases on the web for the record.

Install/update/uninstall entry points (Windows): `get.ps1` (install-or-update, one line),
`uninstall.ps1` (one line, one confirmation), `install.ps1` (does the work; registers in
HKCU\Software\FreeWorks and Settings → Apps). Projects live in `Documents\FreeWorks`.
Release zip: `dev/make_release.sh` → `dist/FreeWorks.zip` → attach to the GitHub release.
